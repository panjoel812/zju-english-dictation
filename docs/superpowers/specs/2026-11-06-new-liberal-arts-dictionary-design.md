# 新文科大英全书词库接入设计

## 目标

将用户提供的《新文科大英全书词表-Unit1-8.csv》接入本地词库页，按 Unit 1–8 分开展示和记录练习进度；在词库页保留一个灰色的“上传词库”入口，点击后显示“敬请期待”，上传能力暂不开放。推文作为独立的可复制文案交付，不触发发布。

## 范围

- 接入 CSV 中去重后的 8 个 Unit，共 770 条词条（703 个单词、67 个短语）。
- 生成项目现有词库格式的静态 JSON，避免运行时解析和新增依赖。
- 新增“新文科大英全书”词库分类，复用现有词库卡片、章节、错题和进度逻辑。
- 在该分类附近增加灰色上传占位按钮，点击打开轻量提示面板，提示“敬请期待”。
- 保留当前所有未发布的题库、去重抽题、导航和输入体验改动。

## 非目标

- 本次不实现用户上传、CSV 解析或云端同步。
- 不发布线上版本，不改版本号，不改变现有词库的练习记录。
- 不把 CSV 的短语拆成单词；短语作为一个可默写词条保留。

## 约束

- 词条使用 `name` 和 `trans` 字段，中文释义合并词性与原 CSV 中文列。
- 每个 Unit 使用独立 ID（`zju-liberal-arts-unit-1` 至 `unit-8`），资源长度与生成 JSON 实际条目数一致。
- 灰色按钮必须有禁用态视觉，点击时仍显示“敬请期待”，不能触发文件选择器。
- 所有修改只保留在本地工作区。

## 方案

1. 静态接入：CSV 转为 8 个 JSON 并注册资源。优点是与现有架构一致、加载稳定、练习数据天然按 Unit 隔离；本次采用此方案。
2. 运行时导入：在浏览器解析 CSV 并写入本地存储。会让上传功能提前可用，超出本次“敬请期待”的范围，并增加解析和错误处理成本。
3. 单文件总词库：只注册一个 770 条词库。实现较少，但失去 Unit 导航和分单元练习进度，不符合课程使用方式。

## 验收

- 词库页出现“新文科大英全书”分类及 Unit 1–8。
- 每个 Unit 的条目数与 CSV 去重结果一致，任意 `english` 不重复。
- 点击灰色上传按钮能看到“敬请期待”，且不会出现文件选择器。
- TypeScript、ESLint、格式检查、构建和现有浏览器回归通过。
